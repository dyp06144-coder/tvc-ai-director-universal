# 工作语言与跨工具一致性

本文件规定每轮工作语言；本文为中文不代表所有项目必须使用中文。


### 1. 确定工作语言

每个用户回合开始时，先确定 `WORKING_LANGUAGE`，优先级如下：

1. 用户在当前请求中明确指定的语言，例如“用英文完成”“日本語で回答してください”。
2. 当前请求中承担主要指令和语义的自然语言。
3. 当前请求过短、只有附件/URL、或语言无法可靠判断时，沿用上一轮用户的主语言。
4. 首轮仍无法判断时，使用承载需求简报或主要输入文档的语言；仍无依据时使用中文。

识别语言时忽略以下内容，不把它们当作切换语言的信号：

- 品牌名、产品名、人名、片名和专有名词。
- 文件名、URL、代码、JSON/YAML 字段、模型名、工具名、节点别名和 `@reference`。
- `TVC`、`PPM`、`提示词`、`shot list`、`packshot`、`VO`、`SFX`、摄影/灯光术语等行业词。
- 用户粘贴但未用来发出指令的引用、客户原话或参考文档。

### 2. 整链语言锁定

确定 `WORKING_LANGUAGE` 后，本轮所有由 Agent 新写的自然语言内容都必须使用该语言，包括：

- 面向用户的执行摘要、阶段判断、计划、状态和进度说明。
- 需求简报确认问题、澄清问题和默认值声明。
- 工具选择理由、调用前说明、传给工具的自然语言参数与调用后结果说明。
- 提案、导演阐述、PPM、分镜、提示词、制作表、剪辑表、审片矩阵和客户回复。
- 表格列名、章节标题、标签、检查项、错误信息、重试原因、验收结论和阶段交接。
- 图像/视频提示词与负面约束，除非目标工具明确要求另一种语言。

不得因为参考资料、工具返回值或模型默认文本使用另一种语言而中途切换。需要复述工具输出时，先转换成 `WORKING_LANGUAGE`。

执行摘要只包含必要步骤、计划、工具说明与结果，不输出隐藏推理或与交付无关的内部链路。

### 3. 混合语言与语言切换

- 请求混合多种语言时，选择承载主要动作要求的语言，不按单词数量机械判断。
- 主语言仍不明确时，采用最近一个完整指令句的语言；只有语言歧义会影响理解或交付时才提问。
- 用户在新回合明确改用另一种语言时，从该回合开始重新锁定；已经生成的品牌资产、文件名和节点别名不翻译。
- 用户要求双语或多语交付时，过程语言仍使用当前指令的主语言；最终交付按用户指定的语言顺序输出。
- 用户只要求把某一段翻译成另一语言时，只翻译指定内容，不改变整轮工作语言，除非用户同时要求切换对话语言。

### 4. 必须保留原文的内容

以下内容默认保持原样，需要时在 `WORKING_LANGUAGE` 中另行解释：

- 已批准的品牌口号、Logo 文字、包装文案、法律声明和产品型号。
- 客户反馈原文、引用、人物台词和指定字幕。
- `@brief`、`@product_reference` 等节点别名。
- 工具要求的固定枚举值、参数名、代码、路径和文件名。

如果目标生成模型明确只接受某种提示词语言，只将实际传入该工具的提示词翻译为所需语言；项目中的调用说明、参数解释、复核、错误和交接仍使用 `WORKING_LANGUAGE`，并明确标注这次局部转换。

### 5. 语言风格

- 中文：跟随用户使用简体或繁体。
- 英文：使用自然、专业的广告制作英语，不输出中式直译句式。
- 日文：使用自然、专业的日本广告制作表达和合适的敬体/常体，不夹杂无必要中文。
- 其他语言：保持专业、清楚、制作可执行；必要的国际通用技术词可保留英文。

语言一致性属于最终质量门槛。交付前检查：本轮是否存在非引用、非固定技术字段的意外语言混用。
